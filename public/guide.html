Настройка приложения «Вместе»

Приложение хранит аккаунты и календарь в Supabase. Для работы сайта создайте свой Supabase-проект и добавьте его публичный ключ в настройки сборки. Пароли и серверные секреты остаются только у вас.

Важно о ключах

Браузеру нужен только URL проекта и ключ Publishable, который обычно начинается с sb_publishable_. Он по назначению виден посетителям сайта. Ключ Secret / service_role обходит политики безопасности и никогда не должен попасть в сайт, GitHub Pages, файл .env этого приложения или чат.

1. Создайте проект Supabase

  1. Создайте аккаунт на supabase.com/dashboard и нажмите New project.
  2. Введите имя проекта, задайте пароль базы и сохраните его в менеджере паролей. Выберите ближайший регион и дождитесь создания.
  3. В проекте откройте SQL Editor → New query.
  4. В репозитории откройте файл supabase/migrations/20260928000000_initial.sql, скопируйте его целиком в окно SQL Editor и нажмите Run. Миграция создаёт таблицы, правила доступа, приватный Storage и Realtime.
  5. Создайте следующий запрос кнопкой New query и выполните файл supabase/migrations/20260929000000_fix_event_save_ambiguous.sql.
  6. В Storage → Buckets проверьте, что появился bucket avatars и он имеет доступ Private. Не включайте Public.

Если первая миграция уже выполнена, не запускайте её повторно: выполните только файл 20260929000000_fix_event_save_ambiguous.sql.

Не отключайте RLS и не добавляйте публичные правила. Миграцию применяют один раз к пустому проекту.

2. Включите подтверждение почты

  1. Откройте Authentication и проверьте настройки провайдера Email: регистрация пользователей разрешена, включено Confirm email.
  2. Откройте Authentication → URL Configuration. В поле Site URL укажите адрес опубликованного сайта. Для проектной страницы он содержит имя репозитория: https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/.
  3. В Redirect URLs добавьте локальный и опубликованный адреса, например http://localhost:5173/** и https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/**. Сохраните изменения.
  4. Для реальной доставки писем настройте собственный SMTP в Authentication → Emails → SMTP Settings или соответствующем пункте Custom SMTP. Тестовая отправка Supabase ограничена. SMTP-пароль храните в Supabase, не в репозитории. См. официальное руководство SMTP.

3. Запустите на компьютере

Установите Node.js LTS и Git. Откройте PowerShell в каталоге проекта и скопируйте файл примера:

Copy-Item .env.example .env
notepad .env

В Supabase откройте Connect или Project Settings → API Keys и скопируйте Project URL и Publishable key. Заполните файл .env так:

VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ваш-ключ

Сохраните .env и выполните команды:

npm install
npm run dev

Откройте адрес, который покажет терминал, обычно http://localhost:5173. Без значений Supabase приложение выводит экран настройки и не выдаёт локальные данные за облачные.

4. Создайте календарь и пригласите партнёра

Зарегистрируйтесь с рабочим email и подтвердите его ссылкой из письма. Первый пользователь нажимает Создать календарь, затем в настройках выбирает Создать одноразовую ссылку. Отправьте её партнёру. Партнёр создаёт отдельный аккаунт и принимает приглашение. Ссылка случайная, действует 7 дней и принимается один раз.

5. Опубликуйте на GitHub Pages

  1. Создайте аккаунт GitHub, репозиторий и отправьте в него файлы проекта. Основная ветка по умолчанию — main.
  2. Откройте репозиторий Settings → Secrets and variables → Actions → Variables. Через New repository variable добавьте VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY.
  3. Откройте Settings → Pages и в разделе Build and deployment выберите Source: GitHub Actions.
  4. Перейдите во вкладку Actions и дождитесь успешного workflow Deploy PWA to GitHub Pages. Адрес появится в Settings → Pages.
  5. Добавьте production-адрес Pages в Supabase Authentication → URL Configuration → Redirect URLs.

Значения Variables видны в публичной сборке, поэтому храните там только URL и Publishable key. Workflow сам выбирает путь для сайта в корне и для адреса с именем репозитория. Подробнее: GitHub Pages с Actions.

Приватность

Политики PostgreSQL RLS применяются при запросе из интерфейса и при Realtime-подписке. Для уровня «Личное» партнёр не получает даже строку времени. Для «Только занятое время» база отдаёт ему только время и признак занятости; имя, описание, место, координаты, теги и напоминания лежат отдельно в таблице, недоступной по его политике. Подробности сюрприза база разрешает читать после срока раскрытия.

Владельцем личной записи остаётся её автор. При параллельном редактировании версия записи проверяется, устаревшая правка вернёт ошибку и не перезапишет более новую. Не меняйте настройки RLS ради упрощения работы интерфейса. Дополнительно: Supabase Row Level Security.

Установка на телефон и работа без интернета

  • Android: Chrome → меню ⋮ → «Установить приложение» или «Добавить на главный экран».
  • iPhone: Safari → «Поделиться» → «На экран Домой» → «Добавить».

Сайт должен быть открыт по HTTPS. Service worker кеширует оболочку приложения, но не ответы Supabase. Для обновления интерфейса обновите страницу после выпуска новой версии. Данные без интернета не редактируются и не синхронизируются позже.

Вход и привязка Telegram Mini App

Чтобы сохранить уже существующий календарь, откройте Mini App у вашего Telegram-бота, войдите по email и паролю, затем откройте Ещё → Настройки → Вход через Telegram → Привязать Telegram. После этого кнопка Продолжить через Telegram будет открывать именно этот аккаунт. Если такого аккаунта ещё нет, та же кнопка создаст новый Supabase-аккаунт автоматически.

Перед использованием владелец проекта должен выполнить миграцию 20260929000002_telegram_auth.sql и развернуть функцию telegram-auth. В Supabase откройте Edge Functions → Secrets и сохраните три секрета:

  • TELEGRAM_BOT_TOKEN — HTTP API token от @BotFather.
  • TELEGRAM_AUTH_SECRET — случайная строка, полученная на компьютере командой node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))".
  • TELEGRAM_APP_ORIGINS — origin сайта и, при необходимости, локального запуска, например https://lovvcurt.github.io,http://localhost:5173. Для страницы https://имя.github.io/репозиторий/ укажите только https://имя.github.io, без пути.

В PowerShell из папки проекта выполните npx supabase login, npx supabase link --project-ref ВАШ_PROJECT_REF и npx supabase functions deploy telegram-auth --no-verify-jwt. Подробная инструкция с пояснениями есть в файле docs/TELEGRAM_MINI_APP.md репозитория.

Секрет бота и случайный ключ хранятся только в Supabase Edge Function Secrets. Не помещайте их в GitHub, сайт, .env или SQL. Telegram-регистрация использует технический адрес почты, который не принимает письма; надёжнее привязать Telegram к вашему существующему аккаунту.

Вход через Telegram на обычном сайте

Эта настройка добавляет кнопку Telegram на обычный экран входа в браузере. Вход по почте и Mini App продолжат работать. Если календарь у вас уже создан, войдите в него по почте, откройте Ещё → Настройки → Вход через Telegram → Привязать Telegram и подтвердите действие. Так Telegram откроет именно старый календарь. Вход Telegram до привязки создаёт отдельный аккаунт.

Если Telegram вы ещё не подключали, сначала выполните в Supabase SQL Editor → New query файл supabase/migrations/20260929000002_telegram_auth.sql. Создайте случайный секрет в PowerShell командой node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))" и сохраните его в Supabase Edge Functions → Secrets под именем TELEGRAM_AUTH_SECRET.

  1. Откройте вашего бота в официальном @BotFather, выберите Login Widget и добавьте сайт в Allowed URLs. Например, для адреса https://lovvcurt.github.io/pair-calendar/ укажите https://lovvcurt.github.io без пути репозитория. Оставьте алгоритм подписи RS256 по умолчанию.
  2. Скопируйте показанный Client ID. В GitHub откройте репозиторий → Settings → Secrets and variables → Actions → Variables → New repository variable. Имя: VITE_TELEGRAM_LOGIN_CLIENT_ID, значение: Client ID.
  3. В Supabase откройте проект → Edge Functions → Secrets и добавьте TELEGRAM_LOGIN_CLIENT_ID с тем же Client ID. Проверьте, что секрет TELEGRAM_APP_ORIGINS содержит домен сайта без пути.
  4. В PowerShell откройте папку проекта и выполните npx supabase login, npx supabase link --project-ref ВАШ_PROJECT_REF, затем npx supabase functions deploy telegram-auth --no-verify-jwt. После отправки изменений в GitHub дождитесь успешного запуска Actions → Deploy PWA to GitHub Pages.
  5. Откройте сайт, нажмите Продолжить через Telegram и подтвердите вход в Telegram.

В GitHub можно добавить только Client ID — это публичный идентификатор. Client Secret, HTTP API token бота и service_role не помещайте в сайт, GitHub Variables, .env или чат. Проверка подписи выполняется на сервере Supabase. Telegram-аккаунт без email нельзя восстановить письмом; сохраните доступ к Telegram. Полное руководство: docs/TELEGRAM_WEB_LOGIN.md.

Push-напоминания и .ics

Для фоновых уведомлений администратор должен один раз настроить публичный VAPID-ключ для сборки сайта, применить миграцию 20260929000001_web_push.sql, развернуть Supabase Edge Function push-reminders и включить Cron. Пошаговые команды есть в разделе «Push-уведомления, если приложение закрыто» файла docs/НАСТРОЙКА.md. На телефоне затем откройте установленную PWA и нажмите Настройки → Напоминания → Включить push на этом устройстве. Партнёр включает его на своём телефоне отдельно. Push — доставка по возможности, а не гарантия точной минуты. На iPhone сайт должен быть добавлен на экран «Домой».

В Настройки → Импорт .ics выберите файл, изучите предварительный просмотр и подтвердите. В Экспорт .ics задайте период и классы событий. Это перенос копии, не двусторонняя синхронизация системного календаря.

Если что-то не работает

  • Экран «Подключите Supabase»: проверьте написание URL и переменных, затем перезапустите npm run dev.
  • Письмо не приходит: проверьте Redirect URLs, папку «Спам» и SMTP.
  • RLS error: примените всю миграцию и проверьте членство двух аккаунтов в одном календаре.
  • Нет синхронизации: проверьте интернет и Realtime в Project Settings → Realtime.
  • 404 GitHub Pages: проверьте Source: GitHub Actions, запуск в Actions и URL, содержащий имя репозитория.
  • Аватар не читается: Storage bucket avatars должен быть Private с правилами миграции.

Резервная копия .ics включает только доступные события; она не сохраняет аккаунты, опросы, идеи, теги и Storage. Проверяйте Database → Backups в зависимости от возможностей вашего плана Supabase и отдельно храните файлы Storage.
