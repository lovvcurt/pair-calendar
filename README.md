# Вместе — календарь пары

Мобильное веб-приложение для двух человек: общий календарь, личные события, голосования, идеи свиданий и важные даты. Интерфейс на русском, тёмная тема включена по умолчанию. Приложение можно установить на телефон как PWA и опубликовать на GitHub Pages. Аккаунты, данные и синхронизация работают через Supabase.

## Возможности

- Регистрация, вход, подтверждение почты и восстановление пароля через Supabase Auth.
- Вход и регистрация по email, из Telegram Mini App и через Telegram на обычном сайте; защищённая привязка к существующему аккаунту через Supabase Edge Function.
- Закрытый календарь на двоих с одноразовыми приглашениями сроком на 7 дней.
- Месяц, неделя и список событий; повторение, место, координаты, теги, несколько напоминаний и автор события.
- Настройки видимости применяются в базе через RLS: подробности, только занятое время или личное событие. Сюрприз скрывает подробности до даты раскрытия.
- Realtime-обновления календаря, опросов и идей, когда приложение открыто.
- Отдельное для каждого аккаунта оформление: тёмный, светлый или системный режим, шесть цветовых палитр и два произвольных цвета для событий участников; выбор синхронизируется между устройствами пользователя.
- Опросы с вариантами и сменой голоса; список идей со статусами; пользовательские цветные теги и важные даты.
- Аватары в закрытом Supabase Storage.
- Импорт и экспорт событий .ics с предварительным просмотром и выбором периода.
- Push-напоминания для закрытой PWA через Supabase Edge Function и Cron; требуется отдельная настройка VAPID-ключей и расписания по [инструкции](docs/НАСТРОЙКА.md#9-push-уведомления-если-приложение-закрыто).
- PWA-оболочка и GitHub Actions для публикации на GitHub Pages.

## Начало работы

Следуйте инструкции [НАСТРОЙКА.md](docs/НАСТРОЙКА.md). Она рассчитана на новичка и объясняет создание аккаунтов, базу Supabase, запуск на компьютере, публикацию и установку на телефон.

Для включения входа через Telegram выполните [настройку Mini App](docs/TELEGRAM_MINI_APP.md) и [входа через Telegram на сайте](docs/TELEGRAM_WEB_LOGIN.md). Оба варианта используют одну привязку аккаунта; без настройки вход по email продолжает работать.

Краткий локальный запуск после настройки проекта Supabase:

    Copy-Item .env.example .env
    # Впишите в .env URL проекта и публичный publishable key из Supabase.
    npm install
    npm run dev

Полный production build:

    npm run build

Если URL и ключ Supabase ещё не заданы, приложение покажет экран настройки со ссылкой на короткое [руководство настройки](public/guide.html). Заглушек и локального хранилища вместо облачной синхронизации нет.

## Дерево проекта

- src — интерфейс React и клиент Supabase.
- supabase/migrations — воспроизводимая схема, функции, RLS, Realtime и правила Storage.
- public — manifest, service worker, иконки и руководство, доступное с опубликованного сайта.
- .github/workflows/deploy.yml — сборка и публикация GitHub Pages.
- .env.example — имена публичных параметров сборки без реальных ключей; приватный VAPID key хранится только в Supabase Edge Function Secrets.

## Ключи и безопасность

Во фронтенде используется только Supabase URL и публичный publishable key. Такой ключ виден посетителям сайта; он безопасен только вместе с корректными правами таблиц и RLS. Никогда не добавляйте secret/service_role key в .env фронтенда, GitHub Variables, репозиторий или Pages. Подробности модели доступа и резервных копий — в [руководстве](docs/НАСТРОЙКА.md#приватность-и-резервные-копии).

Секрет SMTP и пароли аккаунтов хранятся в соответствующем сервисе или менеджере паролей. Не отправляйте их в чат.

## Проверки

Сборка проверяется командой npm run build. Для проверки реального входа, приглашения, RLS, Storage и межустройственной синхронизации сначала нужно создать собственный проект Supabase, применить миграцию и заполнить URL и publishable key. Без таких учётных данных соединение с настоящей базой не заявляется.
