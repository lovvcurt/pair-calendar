# Вход и привязка Telegram в Mini App

Эта настройка добавляет два способа пользоваться календарём из Telegram:

- **Продолжить через Telegram** — при первом входе создаёт аккаунт Supabase, а при следующих открывает тот же аккаунт.
- **Привязать Telegram** — добавляет Telegram как способ входа в уже существующий аккаунт календаря. Пара и её данные не копируются и не объединяются.

Вход выпускает обычную сессию Supabase, поэтому действующие правила RLS и доступ к календарю пары продолжают работать. GitHub Pages исполняет только интерфейс; серверная проверка работает в Supabase Edge Function.

Чтобы добавить эту кнопку и вход через Telegram на сайте в обычном браузере, используйте отдельное [руководство по Telegram Login на сайте](TELEGRAM_WEB_LOGIN.md).

## Что потребуется

- Опубликованный по HTTPS сайт GitHub Pages.
- Созданный через **@BotFather** Telegram-бот с настроенным Mini App. Его **HTTP API token** понадобится только Supabase.
- Настроенный проект Supabase, аккаунт-владелец проекта и Node.js на компьютере.

Если бот ещё не настроен: найдите в Telegram официальный **@BotFather**, выполните `/newbot`, задайте имя и уникальный username, заканчивающийся на `bot`. Сохраните выданный **HTTP API token** в менеджере паролей. Затем отправьте `/mybots`, выберите этого бота → **Bot Settings → Configure Mini App → Enable Mini App** и укажите HTTPS-адрес сайта. В **Bot Settings → Menu Button** (или командой `/setmenubutton`) можно добавить кнопку запуска Mini App. Для входа открывайте Mini App через кнопку бота или Main Mini App; обычная ссылка в браузере не даёт серверу подтверждённые данные Telegram.

## 1. Примените миграцию привязки

В Supabase откройте **SQL Editor → New query**. В репозитории откройте файл `supabase/migrations/20260929000002_telegram_auth.sql`, скопируйте его полностью в запрос и нажмите **Run**.

Миграция создаёт закрытую таблицу соответствия Telegram ID и Supabase user ID. В ней включён RLS, а обычным ролям `anon` и `authenticated` запрещено читать её через Data API. Доступ к ней есть только у Edge Function. В Realtime таблица не публикуется.

## 2. Добавьте серверные секреты в Supabase

Сначала создайте отдельный случайный секрет. В PowerShell, открытом в папке проекта, выполните:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте строку в менеджер паролей. Затем в Supabase Dashboard откройте проект → **Edge Functions → Secrets** и добавьте значения через **Add new secret** (название кнопки может немного отличаться):

| Имя секрета | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | HTTP API token, выданный @BotFather |
| `TELEGRAM_AUTH_SECRET` | Случайная строка, созданная командой выше |
| `TELEGRAM_APP_ORIGINS` | `https://lovvcurt.github.io,http://localhost:5173` |

Замените `https://lovvcurt.github.io` на **origin** своего сайта. Для адреса `https://имя.github.io/pair-calendar/` origin — это только `https://имя.github.io`: без `/pair-calendar/` и без завершающего `/`. `http://localhost:5173` нужен только для локальной проверки; если локально проверять не будете, его можно убрать.

Не вставляйте эти три значения в `.env`, GitHub Variables, SQL, файлы проекта или сборку сайта. Они сохраняются только в **Supabase → Edge Functions → Secrets**. Не отправляйте их в чат. Supabase автоматически предоставляет Edge Function адрес проекта и серверный ключ; ничего вручную копировать для этого не нужно.

## 3. Опубликуйте Edge Function

Откройте PowerShell в папке проекта. В командах ниже `abcxyz` замените на Project ref своего проекта: это часть URL перед `.supabase.co`. Например, для `https://abcxyz.supabase.co` Project ref — `abcxyz`.

Выполните по одной команде:

```powershell
npx supabase login
npx supabase link --project-ref abcxyz
npx supabase functions deploy telegram-auth --no-verify-jwt
```

Если появится ссылка на вход, откройте её в браузере и подтвердите Supabase. Не добавляйте в функцию `service_role` как секрет вручную и не передавайте его в команды. Настройка `verify_jwt = false` нужна потому, что первый вход начинается без Supabase-сессии; сама функция отдельно проверяет подпись Telegram. Действие привязки дополнительно проверяет действующую сессию Supabase на сервере.

После успешной публикации откройте Supabase **Edge Functions** и убедитесь, что `telegram-auth` имеет статус **Active**. Если измените адрес сайта или создадите другой бот, обновите секреты и опубликуйте функцию снова.

## 4. Как пользователю зарегистрироваться или войти

1. Откройте вашего бота в Telegram и запустите Mini App кнопкой **Открыть календарь**.
2. На экране входа нажмите **Продолжить через Telegram**.
3. При первом входе приложение создаст Supabase-аккаунт, имя профиля возьмёт из имени Telegram и откроет обычный экран календаря. Далее можно создать календарь пары и пригласить партнёра.
4. При следующих нажатиях откроется уже созданный аккаунт.

## 5. Как связать Telegram с существующим аккаунтом

Это удобный вариант, если календарь и пара уже настроены по email и паролю:

1. В Telegram откройте Mini App.
2. На обычном экране входа введите email и пароль **существующего** аккаунта календаря.
3. Откройте вкладку **Ещё → Настройки** и карточку **Вход через Telegram**.
4. Нажмите **Привязать Telegram** и подтвердите действие в том же Mini App.
5. Выйдите из аккаунта и нажмите **Продолжить через Telegram**. Откроется тот же календарь и тот же аккаунт Supabase.

Если этот Telegram уже привязан к другому аккаунту, система остановит привязку. Она не переносит данные и не объединяет аккаунты. Войдите в правильный аккаунт и проверьте его состав календаря, прежде чем связывать Telegram.

## Приватность и восстановление доступа

- Сайт отправляет на сервер исходную строку `Telegram.WebApp.initData`. Функция проверяет HMAC-подпись токеном вашего бота и отклоняет устаревшие данные старше часа. Объект `initDataUnsafe` для входа не используется.
- Секрет токена бота находится только в Supabase Edge Function Secrets. В браузер он не передаётся.
- Telegram ID и соответствие аккаунту хранятся в отдельной таблице без доступа у браузерных ролей и без публикации Realtime.
- Для Telegram-регистрации используется скрытый технический email, который не принимает письма. Это не ваш настоящий адрес; пароль генерируется случайно и не показывается. Такой аккаунт можно открыть через привязанный Telegram, но восстановить его по email нельзя.
- Не удаляйте Telegram и не теряйте доступ к нему, если аккаунт создан только через Telegram. Сейчас отвязка и перенос привязки интерфейсом не поддерживаются. Для надёжного восстановления используйте существующий email-аккаунт и привяжите Telegram к нему.
- Функция не отправляет сообщения в Telegram и не включает push. Для уведомлений в чат бота нужна отдельная настройка бота и согласие каждого пользователя.

## Если не получается

- **«Серверная функция … не настроена»** — проверьте три секрета в Supabase и что `telegram-auth` опубликована со статусом **Active**.
- **«Этот адрес не разрешён» или ошибка CORS** — проверьте `TELEGRAM_APP_ORIGINS`. Укажите origin без пути репозитория, например `https://lovvcurt.github.io`.
- **«Откройте Mini App заново» / устаревшие данные** — закройте окно Mini App и откройте его снова из бота.
- **Не подтверждается подпись** — проверьте, что в `TELEGRAM_BOT_TOKEN` вставлен токен именно того бота, который открывает приложение. После исправления секрета опубликуйте функцию снова.
- **Ошибка `telegram_accounts` или permission denied** — выполните миграцию `20260929000002_telegram_auth.sql` в правильном Supabase-проекте.
- **Вход после привязки открывает другой календарь** — проверьте, что перед привязкой вы вошли именно в нужный email-аккаунт. Аккаунты автоматически не сливаются.

Официальные справки: [проверка данных Telegram Mini App](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [секреты Supabase Edge Functions](https://supabase.com/docs/guides/functions/secrets), [развёртывание Edge Functions](https://supabase.com/docs/guides/functions/deploy).
